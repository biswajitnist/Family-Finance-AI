# Architecture

Ledger Local separates deterministic financial operations from optional local
AI assistance.

```text
React UI
  -> FastAPI validation
    -> local document storage / parsing / OCR
    -> deterministic rules
    -> optional Ollama classification
    -> user review
      -> SQLAlchemy / SQLite source of truth
        -> dashboard queries
        -> report exports
        -> finance chat queries
        -> local Help Agent router
          -> markdown help retrieval
          -> SQLite finance queries
          -> extracted text + ChromaDB retrieval
          -> report generation
```

## Accuracy Boundaries

- Money uses `Decimal` and `NUMERIC`, never floating point.
- Transaction amounts are positive; debit or credit determines direction.
- Original imported descriptions are preserved.
- Imports and extracted rows default to unvalidated.
- Duplicate and unvalidated rows are excluded from calculations.
- Rules override local AI classifications.
- Numeric chat answers are generated by database queries.
- Reports are reproducible from validated database records.

## Privacy Boundaries

- Uploaded files, extracted text, the database, and reports stay local.
- Filenames are sanitized and uploads are size and extension validated.
- Frontend responses never expose filesystem paths.
- Ollama is disabled by default and only local endpoints are supported.
- No cloud AI integration exists.
- ChromaDB uses locally computed embeddings and persistent local storage.
- Help Agent synthesis and intent classification use only local Ollama.

## Migration Strategy

SQLite tables are created through SQLAlchemy metadata. Existing Phase 1 tables
receive only additive columns through the startup compatibility migration.
No existing financial rows are deleted or rewritten.
